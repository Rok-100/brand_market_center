# 协作与发布规范

## 1. 开始任务

1. 先从 `main` 拉取最新代码。
2. 每个问题单独建立分支：修复使用 `fix/问题名`，新功能使用 `feat/功能名`。
3. 不要把多个无关问题混在同一次提交中。

## 2. 修改与自检

1. 保留现有工作流和历史数据兼容性。
2. 不提交 `.env`、账号配置、Token、Cookie、素材库数据库、上传视频或生成结果。
3. 运行 `powershell -ExecutionPolicy Bypass -File tools/run-tests.ps1`。
4. 用同事身份至少走通受影响功能的完整操作流程，并记录结果。

## 3. 合并请求

合并请求需写清：

- 修复或新增了什么；
- 影响哪些页面和接口；
- 做了哪些自动测试和真实操作验证；
- 是否涉及配置、数据库、素材迁移或线上发布。

由 `shuhao` 审核后合并到 `main`。未经审核，不直接修改主分支。

## 4. 发布

1. 合并后更新版本号与更新说明。
2. 先在测试环境验证登录、产品镜、KOC、视频裂变、明星画面、素材中心和智能混剪。
3. 备份当前线上版本，再发布新版本。
4. 发布后回读 `/api/ready`、首页和受影响页面，确认真实可用。
5. 失败时立即回退到上一版本，不在生产环境继续试错。
