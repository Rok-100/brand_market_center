# WIS Effective Copy Remix

## 目标

把历史有效文案当作“成交结构证据”，而不是可直接照抄的句子库。先锁定母版的吸引与成交因果，再在真实商品资料和合规边界内生成能直接说出口、能承接镜头、能解释创新来源的二创文案。

## 必读顺序

每次生成或审查文案，先读取：

1. `references/generation-contract.md`
2. `references/sku-boundaries.md`
3. `references/workbench-system-prompt.md`

需要选择历史母版或解释历史有效逻辑时，再读取：

4. `references/corpus-map.md`
5. `references/mother-patterns.md`

发现低效、同质化或合规风险时，再读取：

6. `references/negative-patterns.md`

不要一次性加载与当前品类无关的所有原始案例。按产品、钩子和任务类型选择最小相关部分。

## 输入门禁

生成前取得以下信息：

- 目标SKU与允许使用的口播简称
- 发布渠道、视频时长和目标条数
- 母版视频逐字稿或可靠转写
- 母版说话人、人物关系、场景关系和镜头功能顺序
- 已确认卖点、产品使用方法和可拍证据
- 当日真实价格、数量、赠品、库存和截止时间；没有则明确选择“不说机制”
- 必须保留项与允许变化项
- 禁用词、授权限制及其他合规边界

缺少商品、价格、授权或功效事实时，不猜测、不用历史语料补齐。使用 `[待提供：具体字段]`，或输出不依赖该事实的版本。

## 工作流

### 1. 逐字保全母版

先保留完整逐字稿，再做结构分析。不得把摘要当原稿，也不得从句子中间开始。把母版拆成有时间顺序的 `copy_beats`：

`hook → recognition/problem → trust → product/evidence → experience/benefit → offer → cta`

不是每条母版都包含全部节点。只记录真实存在的节点，不为了套模板虚构内容。

### 2. 分离不变量与变量

不变量通常包括：

- 钩子的心理功能
- 目标人群与主问题
- 说话人身份和第一/第二/第三人称视角
- 人物功能关系
- 情绪触发和升级方式
- 产品出现节点
- 证据顺序
- 异议处理与成交顺序
- 动作因果和镜头功能顺序

变量通常包括：

- 原句措辞和句式表层
- 具体生活场景
- 人物外观、服装和道具
- 同功能的痛点瞬间
- 同证据类型的镜头表现
- 经确认的商品事实与当日机制

把“厨房、蓝衣服、某明星姓名、原价格、原产品名”写进不变量，通常是错误的；只有它确实承担不可替代的身份或剧情功能时才保留。

### 3. 匹配历史结构

从 `mother-patterns.md` 选择一个主结构，必要时增加一个辅助结构。优先级：

1. 与当前母版心理功能相同
2. 与目标SKU和视频时长相容
3. 有S级数据或A级有效标记支持
4. 能由现有镜头证明
5. 风险和事实依赖可控

不要因为某个历史词频高就选它。高频词可能已经饱和。

### 4. 生成三档二创

**稳健版。** 保留母版节点、顺序、说话视角、情绪强度和主要句式；只替换经确认的商品事实及少量表层表达。目标是母版逻辑高还原。

**均衡版。** 保留全部关键节点和成交顺序；只选择一个主要创新轴，例如生活瞬间、反常识角度、信任证据、可拍实验或收口方式。不要同时重写所有节点。

**大胆版。** 可以重写原句与表现形式，但必须能建立逐节点映射，证明新文案仍完成同样的心理任务、人物功能和成交因果。大胆不是更夸张，也不是增加未经证实的事实。

默认配比为稳健40%、均衡40%、大胆20%。用户指定数量或比例时以用户为准。

### 5. 写成能说出口的中文

- 前0.5秒开始说话，前三秒只建立一个强相关问题或悬念
- 每句尽量只承载一个信息
- 优先短句、动词、具体部位、具体时刻和真实动作
- 使用口语停顿，不写报告腔、成分说明书腔或连续排比
- 技术名词必须翻译成“解决哪一步问题＋镜头怎么证明”
- 价格和规格必须逐字使用已确认口径
- 文案长度按普通中文口播约每秒4至5个有效汉字估算，并给动作、停顿留时间

### 6. 同步镜头证据

每个主卖点至少对应一个可拍证据。不能只说“服帖”，要写鼻翼、下巴、眼周是否翘边；不能只说“精华多”，要说明取出、展开、挤压或敷后膜布变化；不能只说“补水”，要连接妆前卡粉、洗脸紧绷或空调房等可感场景。

如果当前素材无法证明某句话，改写文案或标为待补镜头，不要让口播先行承诺。

### 7. 交付并说明

按 `generation-contract.md` 输出。每条至少包含：

- 三秒钩子
- 完整口播
- 节奏/停顿提示
- 母版节点映射
- 创新点
- 镜头证据
- 事实来源或待确认项
- 风险提示

除非用户只要成稿，否则不要只给裸文案。

### 8. 校验

生成结构化JSON后运行：

```powershell
$py = "C:\Users\202606\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
& $py scripts\validate_copy_batch.py --input batch.json
```

脚本检查字段完整性、跨SKU敏感词、未确认机制、重复度、占位项和口播长度。脚本通过不代表商品事实或广告合规已经审核；人工仍要确认商品真值、授权和当日活动。

## 不可突破的边界

- 不把历史“有效”写成今天仍有效的保证
- 不把历史素材中的明星、采访、销量、检测或推荐关系当作已授权事实
- 不跨SKU迁移成分、技术、膜布、功效、用法或机制
- 不制造假新闻、假采访、假库存、假限时或绝对担保
- 不用焦虑词替代具体问题，不用技术堆砌替代用户认领
- 不为追求“创新”破坏母版说话视角、角色功能和成交顺序
- 不因相似度高就判定有效，也不因措辞新就判定创新

## 历史语料解释口径

语料分为S/A/B/C四级，详见 `corpus-map.md`。S级只表示源表中同时存在投放和成交数据；A级只表示被源表标注为爆款或有效；B级只迁移结构；C级只用于反例。不同账户、时段、人群、出价和承接环境不可直接横向归因。
