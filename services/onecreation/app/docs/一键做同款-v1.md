# 一键做同款 v1 产品与技术契约

## 1. 目标

“一键做同款”是中枢平台“一创制作”的第 5 个制作板块。它不是另一套通用视频生成模板，而是把已经成功的 LibTV 视频节点视为可执行经验，复用该节点的：

- 原始视频提示词；
- 模型、生成模式、清晰度、时长、声音开关和高级参数；
- 全部上游图片、视频、音频；
- `nodeKey` 引用和混合输入顺序；
- 成功结果与后续人工选择。

v1 支持六种已经闭环的变更白名单：仅换产品、仅换口播、换产品 + 口播、仅换背景、换人物、换背景 + 产品。每种类型都有独立的目标资产输入、上游承载图判定、提示词锁定规则和 LibTV 节点绑定，不允许只开放选项而没有执行链。

页面固定使用四个顶层业务阶段：

1. `01 提交成功画布`：提交 URL、成功 TaskID 与做同款类型；
2. `02 源画布拆解`：校验访问权限、命中成功节点、审计全部上游资产并创建或恢复任务画布；
3. `03 确认上游资产`：依次完成目标配置、产品形态与 nodeKey 映射、候选资产与最终提示词核实；这三项是同一业务阶段的三个子步骤，不另占顶层编号。进入视频生成或终态后，页面仍保留紧凑版阶段 03 摘要，展示目标 SKU、节点映射、OSS 直连、候选图核实和最终确认数量，不得把已执行步骤从页面清空；
4. `04 同款结果输出`：展示任务级失败原因、单目标失败与重试入口，或成功视频、任务画布和下载地址。

后台状态可以比四个顶层阶段更细，但页面不得把内部状态误展示成第 5、6 个业务阶段。

## 2. 两种入口

### 2.1 完全新建

1. 用户输入 LibTV 画布 URL、成功视频 TaskID 和本次变更类型。
2. 后台只通过官方 `libtv` CLI 校验登录、画布、视频节点和 TaskID。
3. 创建独立任务，任务名沿用 AI-KOC 的“月日 + 当日序号”规则（例如 `0831任务一`）；按 TaskID 精确定位成功节点，读取提示词、参数、结果与上游输入，并在同一 `spaceId` 创建该任务唯一的 LibTV 项目/画布。任务接口持续回传该画布地址。
4. Qwen 3.7 Plus 多模态审计首帧、尾帧、关键帧和场景图是否承载旧产品、可替换背景或人物身份；模型不可用时采用保守策略，按本次变更角色把全部上游图片列入人工确认。
5. 源画布拆解区只读展示完整原始视频提示词并提供一键复制；创建任务时智能识别原片产品并从可替换 SKU 中剔除。目标配置区为每个剩余 SKU 编译独立的完整 `variant_prompt`，统一命名为“新视频提示词（核实口播文案）”。用户可直接核实和修改，各 SKU 的文本互不覆盖。
6. 用户按复刻类型配置资产：换产品时选择一个或多个目标 SKU 和 OSS 产品资产；产品图一律不默认勾选，即使标记为“平台推荐”也必须由用户手动选择，每个已选 SKU 至少勾选一张图才允许提交；每个 SKU 的产品图只展开前两行，更多图片在卡片内通过右侧纵向滚动条继续选择；换背景或人物时上传 1–3 张对应参考图，可追加替换说明。
7. Qwen 3.7 Plus 按参考画布复刻 skill 的规则，把只读源提示词最小改写为每个 SKU 可直接提交的完整 `variant_prompt`：
   - 生图提示词；
   - 产品真实尺寸与原片占画比例方案；
   - 旧产品/旧背景/旧人物残留、包装身份、数量、接触阴影和人物混脸检查项；
   - 删除旧产品名称、别名、包装、尺寸、数量和标签事实，写入目标 SKU 的资料卡事实；
   - 保留源镜头、动作、构图、节奏、人物、背景、口播顺序和全部逻辑 `nodeKey`；
   - 输出完整最终提示词，而不是在源提示词后追加“目标适配补充”。
8. 每个承载本次待替换对象的上游图生成 2 张候选图。主模型为 GPT Image 2；失败自动回退 Seedream 5.0 Pro。
9. 页面必须等待用户逐张选择候选图，同时展示该 SKU 的最终 `variant_prompt`。用户可以直接修改，但不能保留已识别的旧产品事实，也不能删除新增背景/人物节点引用。用户确认前，不创建或运行视频节点。
10. 确认后，所有 SKU 都进入任务创建时的同一个画布；平台为每个 SKU 上传一组带 SKU 前缀的上游节点，并发创建独立视频节点。最终提示词只做逻辑 `nodeKey` 到该任务画布真实 `nodeKey` 的确定性替换，不再经过隐藏的第二次 Qwen 改写。视频节点沿用源节点同模型、同模式和同参数。
11. 下载结果到平台输出目录，页面回传任务画布地址、各 SKU 成片预览与下载；LibTV 视频节点名和下载文件名必须包含 SKU 产品名称。

任务画布创建必须满足幂等恢复契约：新任务的画布名由可读任务名与稳定任务身份后缀共同组成，避免两个不同任务即使显示名相同也串用画布；先以精确画布名执行 `libtv project list`，没有同名画布时才执行一次 `libtv project create`；创建响应兼容 `uuid / projectUuid / projectId / id` 及常见嵌套结构；若响应没有 ID，必须再次按精确名称回查并采用最近更新项。失败任务重试也先回查同名画布，禁止因为返回字段差异重复创建。升级前已存在的任务没有身份后缀，继续用旧画布名恢复；若历史故障已产生多个同名画布，记录数量并恢复最近更新项，后续任务仍只绑定一个 `projectId`。

目标 SKU 目录必须以产品基础目录与 OSS 资产管理目录的合并结果为准：基础目录继续保留既有正式产品；资产管理目录中处于启用状态且至少有 1 张图片的 SKU 必须补入一键做同款，零图片占位 SKU 不进入可选目标。当前 OSS 已核实 `WIS美白针` 有 5 张图片，因此总可用目录为 7 个 SKU；原片为燕窝面膜时应剔除原片并展示其余 6 个目标。

LibTV CLI 回传必须兼容纯 JSON、带进度文本的 JSON 和多段 NDJSON，并取最后一个完整业务 JSON。`node create --run` 退出码为 0 但回传不可解析时，禁止再次创建节点；先按任务画布 `projectId + 精确节点名` 回查。失败任务重新发起时也先回查上一次已提交的节点，能取得成片即直接恢复下载，只有确认上一次节点不可恢复时才允许进入新一次生成。诊断日志需保留清洗后的退出码、stdout 与 stderr 片段。

### 2.2 历史任务做同款

历史页以初次上传的标准化画布 URL（spaceId + projectId）和精确 TaskID 所形成的 `source_ready` 模板为唯一案例卡片。该模板产生一个或多个 `completed` 正式案例后，历史页把最新成片回填到原模板卡片并显示“已生成成片”，不再额外展示派生案例卡片；各目标成片的正式提示词记录继续独立保留在提示词库。仅拆解模板不会进入正式提示词库。点击“重新审计并做同款”后：

- 复用该案例的源画布地址和 TaskID，重新读取成功视频节点，并按当前规则逐张独立审计全部上游图片；禁止复制历史模板中的旧资产判断；
- 不再要求用户重复输入 URL 和 TaskID；
- 先创建新任务并立即跳转到该任务工作区，上游复审、任务画布准备与初始提示词编译继续在后台执行；
- 复审结果覆盖原 `source_ready` 模板的审计快照，必须保留原模板 ID、名称、标签、创建时间与归属，不新增重复模板；
- 仍需重新选择本次目标 SKU、核实每个 SKU 的新视频提示词，或上传本次背景/人物参考图；
- 本次变更对象的承载图仍要生成候选并经过人工确认；
- 后续执行链与完全新建一致。

历史模板支持按完整画布 URL、TaskID、视频/模板名称和标签搜索，并提供分页。模板归属人可修改自己模板的视频名称；实名历史管理员可修改所有可见模板的名称，并继续承担跨账号标签和删除治理。名称修改会重建 JSON 快照、更新 OSS 对象和数据库检索索引。

任务列表新提交来源前必须以“规范化画布 URL（spaceId + projectId）和 TaskID”共同判重。当前账号可见范围内已有相同来源模板时，允许创建新的同源复审任务，重新访问 LibTV 画布并按当前规则逐图审计；复审结果只更新已命中的原模板，不新增重复模板。界面明确提示“已找到相同来源，将按当前规则重新审计并更新原历史模板，不会重复收录”。管理员按跨账号可见范围判重，普通用户按本人模板范围判重。

## 4. 提示词与正式案例存储位置

### 4.1 当前 v1 落地

- 任务快照：`app/jobs/one-click-remake-job-<jobId>.json`
- 正式案例本机回退/待同步清单：`app/jobs/one-click-remake-prompt-library.json`
- 正式案例不可变 JSON 快照：阿里云 OSS 的 `yxb/workbench/one-click-remake/prompt-recipes/<YYYY-MM>/<ownerKey>/<recipeId>-<sha256>.json`
- 正式案例数据库索引：素材中心 MySQL 表 `ai_remake_prompt_recipes`
- 候选图：平台输出根目录下的 `一键做同款/<jobId>/candidates/`
- 从源画布下载的复用资产：`一键做同款/<jobId>/source-assets/`
- 用户上传并固化的背景/人物参考图：`一键做同款/<jobId>/replacement-assets/`；共享存储可用时同步至 OSS 的 `one-click-remake-<role>-references` 分类。
- 结果视频：`一键做同款/<jobId>/results/`
- 目标产品原始资产：继续引用现有 OSS 资产图库，不重复写入提示词库。

任务和案例均记录 `ownerKey`，用于归属、管理权限和审计；“历史任务做同款”与正式提示词库读取全员共享案例，任务工作区仍只返回当前工作台账号的数据。服务重启会恢复任务快照；执行中的任务会被标记为“已中断”，不会错误显示为仍在运行。

视频成功后先写本机案例和版本快照，再分别同步 OSS 与数据库。两者任一暂不可用都不会把已经成功的视频改判为失败；案例会显示 `database_only`、`oss_only` 或 `local_fallback`，服务重启后自动重试最近的待同步案例。

### 4.2 正式案例记录内容

正式案例有两条明确入库路径：一是视频成功生成、成片下载完成并由用户在人工质检窗口确认“符合要求并归档”的目标成片；二是归属人或管理员显式选择源视频、源提示词、OSS 快照与数据库索引均完整的成功拆解模板，将其提升为独立的 `source_curated` 正式案例。第二条路径只复用已经成功的原视频和原提示词，不伪造人工质检或目标 SKU 生成记录，原 `source_ready` 历史模板保持不变。第一轮目标成片人工通过时直接完成，不生成第二轮；第一轮人工判定不符合时才按人工意见生成第二轮；第二轮仍不符合时保留两轮结果待处理且不入库。AI 质量检验只提供分数、维度和修正建议，不再自动归档或自动触发第二轮。案例包含：

- 源画布 URL、spaceId、projectId、TaskID、成功视频节点；
- 源模型、模式、设置、高级设置和原始视频提示词；
- 上游资产的 `nodeKey`、类型、角色、顺序、尺寸，以及产品/背景/人物承载判定；
- 目标 SKU 资料快照和所用 OSS 产品资产引用；
- 背景/人物参考图的逻辑 `nodeKey`、OSS 引用、存储状态与用户补充说明；
- 每张重建图的 Qwen 生图提示词、负面约束、尺寸方案、输入顺序、验收清单；
- 用户最终选择的候选图；
- 视频提示词的不可变源文本、用户编辑底稿、编译基线、用户最终确认文本、编辑状态、替换记录和警告；
- 任务唯一共享画布、SKU 视频节点、结果视频和所属任务。

### 4.3 检索与共享

提示词库已支持数据库分页检索，条件包括：

- 提示词、场景、动作、产品、节点名称、源画布 URL 和 TaskID 的多关键词包含检索；
- 目标 SKU、复刻类型、视频类型、源模型和源 TaskID 精确筛选；
- 创建日期范围筛选；
- 每页 1–50 条的全员共享分页；归属字段和实名管理员权限继续用于修改与删除治理。

数据库不可用时，同一套条件自动作用于本机 JSON 缓存，并在页面明确标记“本机缓存回退”。当前版本实现的是关键词和结构化字段检索，尚未加入向量语义检索；后续可在成功案例量足够后增加 embedding 索引，而不改变现有案例数据契约。

页面查看时可逐项展开生图提示词、源视频提示词和同款视频提示词；已同步 OSS 的案例还可打开结构化 JSON 快照核对完整记录。历史模板和正式提示词库使用同一检索索引：历史页按源模板关联 `source_ready` 与目标成片 `completed` 并折叠为一张卡，正式提示词库返回全员共享的 `completed` 与 `source_curated` 提示词记录，原始 `source_ready` 模板不会直接混入正式库。

正式案例治理沿用案例 `ownerKey` 与一键做同款实名管理员白名单：案例归属人可新增、删除自己的正式案例，管理员可跨归属操作，其他用户只读。新增不是手工拼装提示词，只能从平台中已经人工质检通过且仍保留完整成片与编译提示词的任务结果，或源视频、源提示词、OSS 快照和数据库索引均完整的成功拆解模板重新归档；确定性案例 ID 保证重复提交幂等。删除只移除正式案例的 MySQL 检索索引、OSS JSON 快照与本机案例缓存；目标成片路径保留原任务、成片和人工质检记录，成功拆解模板路径保留原 `source_ready` 历史模板，因此归属人或管理员后续仍可重新加入。管理员代操作不会改变案例归属。

## 5. 智能处理边界

### 收集阶段

- URL 只负责定位画布；TaskID 负责定位成功视频节点。
- 不能按节点名称猜测成功结果。
- 收集源节点全部输入与顺序，不能只取首帧或产品图。

### 整理阶段

- Qwen 负责视频类型和产品/背景/人物承载图审计、资产角色、尺寸方案，以及从只读源提示词到每个 SKU 完整 `variant_prompt` 的最小改写。
- 目标产品事实只取平台产品资料与已选 OSS 资产。
- 一键做同款 SKU 目录合并 OSS 资产管理中的有图产品；产品图必须由用户显式勾选，后台不得以第一张图兜底。
- Qwen 返回结构化 JSON；缺字段、口播未逐字保留或生图提示词为空时阻止后续提交。
- 对独立产品资料节点，`product_asset / product_reference / packshot` 等角色和资料图名称是确定性业务证据；当模型同时返回 `productBearing: false` 时，以独立产品资料角色为准，仍进入目标 SKU OSS 原图直连与人工核实，禁止原样复用旧产品资料图。
- 用户编辑只改变目标视频提示词底稿与最终生成文本，不覆盖溯源得到的原始提示词。

### 重建阶段

- 图 1 始终是源画面，后续依次为目标产品、目标背景、目标人物参考，顺序写入提示词库。
- 每张本次变更对象承载图生成 2 个候选。
- 人工确认是硬闸门；不是可隐藏的提示。
- 源提示词始终只读保留；每个目标 SKU 使用独立、可编辑的完整 `variant_prompt`。后台校验提示词非空、已识别的源 SKU 无残留、新增背景/人物 `nodeKey` 引用仍在。
- 用户确认后的 `variant_prompt` 就是该 SKU 视频节点的最终业务提示词；提交 LibTV 前只允许做逻辑 `nodeKey` 到真实 `nodeKey` 的确定性映射。平台追加形态映射、几何和数量说明后必须再次将源产品全部别名替换为目标 SKU 正式名称并执行残留校验；兼容旧任务时只自动清理平台形态映射行中的历史源 SKU 标签，用户在自由正文重新写入旧产品仍须阻断。
- 视频节点沿用源模型与参数，不切换为平台通用模板。
- 一个任务对应一个 LibTV 画布；一个或多个 SKU 对应同一画布内不同的视频节点，允许并发等待生成，重试也继续使用该任务画布。
- `node create --run` 回传异常时先从同一画布按精确节点名恢复，重试也先恢复上一节点，避免重复生成和重复扣费。

## 6. 后台状态与进度

核心状态：

`auditing/creating_task_canvas → awaiting_configuration → preparing_mapping → awaiting_mapping_confirmation → preparing_assets → awaiting_asset_confirmation → generating_video → success/partial_success/failed`

页面每 2 秒轮询；离开页面不会中断后台任务。可展开查看：画布拆解、提示词编译、候选图生成、视频生成与下载耗时，以及逐阶段事件日志。

## 7. API

- `GET /api/one-click-remake/config`
- `POST /api/one-click-remake/jobs`
- `GET /api/one-click-remake/jobs`
- `GET /api/one-click-remake/jobs/:id`
- `POST /api/one-click-remake/jobs/:id/prepare`
- `POST /api/one-click-remake/jobs/:id/confirm`
- `GET /api/one-click-remake/jobs/:id/candidates/:targetId/:sourceNodeKey/:index`
- `GET /api/one-click-remake/jobs/:id/results/:targetId`
- `GET /api/one-click-remake/history`
- `POST /api/one-click-remake/history/:recipeId/remake`
- `GET /api/one-click-remake/prompt-library?keyword=&productId=&changeType=&videoType=&model=&taskId=&dateFrom=&dateTo=&page=&pageSize=`
- `GET /api/one-click-remake/prompt-library/candidates`：返回当前用户可治理的人工质检通过成片，以及源视频、提示词与共享快照完整的成功拆解模板；管理员可跨归属读取。
- `POST /api/one-click-remake/prompt-library`：按 `jobId + targetId` 新增或恢复目标成片正式案例，或按 `sourceRecipeId` 提升成功拆解模板。
- `DELETE /api/one-click-remake/prompt-library/:recipeId`：由管理员或案例归属人删除正式案例，原任务与成片保留。

背景/人物参考图先通过通用上传接口提交，`kind` 分别为 `remake-background`、`remake-person`，上传会话固定为 `one-click-remake-<jobId>`；服务端在 `prepare` 阶段再次校验文件必须属于当前任务，防止跨任务路径复用。

`prepare` 请求中的每个目标可提交 `videoPromptDraft`、`videoPromptSourceProductId`，任务级提交 `sourceProductId`。未提交目标提示词时回退到该 SKU 已编译的 `variant_prompt`，不再回退到未换品的源提示词。`confirm` 请求通过 `videoPrompts[targetId]` 提交用户最终编辑文本，后台校验后才进入视频节点生成。
