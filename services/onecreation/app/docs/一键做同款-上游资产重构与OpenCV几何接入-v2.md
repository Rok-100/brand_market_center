# 一键做同款：上游资产重构与 OpenCV 几何接入 v2

版本：v2（2026-09-02）
状态：已在 `feat/remake-global-asset-rebuild-v21169` 实现，待合并、部署与线上验收；透明袋测试仅为回归夹具，不是生产规则

## 1. 目标

“一键做同款”以成功 LibTV 视频节点、原提示词、真实上游 nodeKey 顺序、上游资产、模型和参数为最高事实来源。用户选择“仅换产品”时，只改变含产品的上游图片及视频提示词中的产品描述；选择“换产品 + 口播”时，再逐字替换口播。未在白名单内的镜头、人物、背景、动作、构图、时长和参数保持不变。

阶段仍为：

1. 01 提交成功画布
2. 02 源画布拆解
3. 03 确认上游资产
4. 04 同款结果输出

OpenCV 只接入阶段 03 的含产品场景图重构，不进入最终视频提示词。

## 2. 已确认的生产决策

### 2.1 数量策略

默认策略为 `inherit_source_observation`：每张源图独立继承该图实际可见的产品实例及槽位。

- 不使用投影面积、体积、SKU 名称或物理尺寸自动推导目标数量；
- 不存在写死的 2、15、27 或其他产品数量；
- 不把一张图的数量扩展为整段视频或其他节点的数量；
- 无法可靠计数时不猜数，按已可靠定位的实例处理或转人工核实；
- 数量调整若未来提供，只能是用户主动开启的独立高级能力，不属于默认一键做同款。

阶段 03 提交映射前必须核对 `productCount` 与有效 `productInstances` 数量。两者不一致时标记 `count_conflict`；没有有效实例框时标记 `missing_instances`。这两种状态都必须阻止候选资产准备，并在对应源节点提供“重新识别数量与槽位”；已经存在可靠实例框时，同时提供“人工确认按 N 个可靠实例执行”。人工确认只把该源图的观察数量修正为有效实例框数量，不改变源节点、目标 SKU 或其他拆解事实。重新识别仍不一致时继续阻断，禁止把冲突配置再次提交给 OpenCV。

透明袋案例里的固定产品、数量、坐标、多边形、接触线和本机目录全部是测试夹具，生产代码不得引用。

### 2.2 布局策略

默认策略为 `preserve_source_slots`：对当前源图中的每个可辨识旧产品实例进行一对一替换，并继承中心、接触点、承托面、遮挡层级、朝向、间距和整体占用区域。目标产品按自身真实包装比例进入对应槽位，不通过拉伸、压扁或跨图数量换算适配。

### 2.3 提示词分层

平台必须隔离：

- `asset_generation_prompt`：仅用于某一张上游图的产品重构，可包含几何比例、当前源图槽位、遮罩、布局和形态映射；
- `video_variant_prompt`：仅用于最终 LibTV 视频节点，只保留源视频镜头和动作的最小产品/口播替换。

下列内容禁止进入 `video_variant_prompt`：

- 平台产品几何硬锁；
- 平台内部产品形态映射说明；
- OSS asset ID；
- OpenCV 坐标、遮罩和布局参数；
- 自动数量控制模板或整段视频数量约束。

## 3. 完整上游资产路由

阶段 03 必须列出全部上游资产，每个 nodeKey 只能走一条路由：

| 路由 | 条件 | 动作 |
| --- | --- | --- |
| `reuse_source` | 不含本次替换对象 | 原图复用，不调用 OpenCV 和生图 |
| `oss_direct` | 独立产品白底图、包装图或资料图 | 目标 SKU 原始身份图直连，不生图 |
| `generated_candidate` | 场景图中存在源产品像素 | OpenCV 几何准备后，每轮生成 2 张候选 |
| `manual_review` | 证据不足且无法确定 | 阻断并等待人工确认 |

审计不能只相信 `productBearing`。审计理由或证据明确出现旧产品像素、旧包装或人物手持旧版产品时，即使布尔字段为 false，也必须纠正为含产品并进入重构；该节点禁止切换为源图直通。明确“不含、没有、未见旧产品”的否定证据不得误触发。

生成视频前保存 `one-click-remake-upstream-manifest-v2`，校验源资产数量、逐 nodeKey 路由、首轮候选数量和最终选择。任何应重构节点缺组、冲突节点直通或首轮不是 2 张，都必须阻断。

### 3.1 全类型溯源与文本节点规则（2026-09-07 补充）

“完整上游资产”不得等同于“媒体文件”。源视频节点参数中的 `imageList`、`videoList`、`audioList`、`textList` 与 `mixedList` 都必须进入同一条 nodeKey 溯源链；提示词引用但上述载荷中不存在的 nodeKey 也必须形成显式冲突，禁止过滤或静默跳过。`mixedList` 负责恢复跨类型输入顺序，各类型 order 只作为缺失顺序时的补充。

文本节点必须保留 `data.content` 的字符串数组、原始条数、顺序及其中的 `{{Node ...}}` 引用。按目标 SKU 编译时只允许调整产品身份、包装层级、形态、数量、产品专属动作，以及用户明确要求的新口播；人物、场景、镜头、非产品道具和故事结构继续锁定。确定性 SKU 名称替换是模型不可用或模型结果不合格时的安全回退，不代表可以放弃冲突检查。

下列文本状态必须在阶段 03 的完整上游资产清单中可见：

- `text_rewrite`：已写入目标 SKU 内容，生成时创建目标 text 节点；
- `text_reuse`：确认不涉及本次变更，仍显式创建或复用可追踪的 text 节点；
- `text_conflict`：存在旧 SKU 残留、其他 SKU 混入、包装/动作/数量矛盾、源载荷冲突或文本缺失，阻断确认；
- `unsupported`：未知上游类型或提示词引用缺少载荷，阻断并显示“已阻止静默丢失”。

上游 manifest 升级为 `one-click-remake-upstream-manifest-v2`。最终生成对每个受支持 nodeKey 建立源到目标映射：文件型资产先上传或直连，文本资产通过官方 LibTV CLI 创建 `type=text` 节点并写入目标 `content`，再统一替换视频提示词中的 nodeKey、按原输入顺序连接。运行时遇到未支持类型必须抛错，不能 `continue`。

源拆解快照只有覆盖当前源参数中的全部上游节点才可复用；旧快照若漏掉文本，不得被完整性检查误判为可直接复用。已经停在阶段 03 的落盘任务可在启动时从其已保存源参数回填文本及显式冲突，不重新访问源画布、不重做图片候选；用户确认资产前再补做目标 SKU 文本语义改写和冲突复核。

## 4. OpenCV 平台协议

平台通过可选内网服务 `POST /v1/product-geometry/prepare` 调用 OpenCV。服务 URL 使用 `ONE_CLICK_REMAKE_GEOMETRY_URL` 配置，超时使用 `ONE_CLICK_REMAKE_GEOMETRY_TIMEOUT_MS`，默认 30 秒。

请求使用 `one-click-remake-geometry-v1`：

```json
{
  "schemaVersion": "one-click-remake-geometry-v1",
  "policy": "preserve_source_slots",
  "quantityPolicy": "inherit_source_observation",
  "sourceNodeKey": "scene-a",
  "sourceImageUrl": "https://.../source.png",
  "sourceWidth": 1080,
  "sourceHeight": 1920,
  "observedCount": 2,
  "sourceInstances": [
    {
      "id": "source-instance-1",
      "bbox": { "x": 0.1, "y": 0.4, "width": 0.2, "height": 0.3 },
      "contactPoint": { "x": 0.2, "y": 0.7 },
      "occlusionOrder": 1,
      "visibleRatio": 0.9,
      "confidence": 0.92
    }
  ],
  "target": {
    "productName": "目标 SKU",
    "fixedLengthWidthHeightRatio": [2, 2, 13.5]
  },
  "productReferenceUrls": ["https://.../target-front.png"]
}
```

实例坐标为当前源图归一化坐标，不得复用测试坐标。没有可靠实例时传空数组，不得伪造。

响应返回容器内网 HTTP 产物地址，包括布局层、编辑遮罩、产品保护遮罩、融合环、阴影提示和预览。平台兼容 camelCase 和 snake_case 字段，但不会把 `http://product-geometry:8000/...` 直接交给外部生图模型：平台先下载用于生成的布局层，再通过当前用户的生图凭据上传到生图提供方，模型只接收提供方可访问的 URL。包含源图的预览只用于审计，不作为模型参考输入，避免旧产品像素二次污染。

配置了几何服务但未返回布局层、平台无法下载、无法上传到生图提供方时，资产准备失败并明确报错；未配置服务时任务记录 `not_configured`，使用源图 + 目标身份图 + 逐槽位提示词的能力降级路径，不宣称完成了像素级遮罩编辑。

实现位置：

- 平台协议与清单：`app/one-click-remake-geometry.js`；
- 平台编排与提供方素材暂存：`app/one-click-remake.js`；
- OpenCV 服务：`services/product-geometry/app.py`；
- 容器接入：`services/product-geometry/Dockerfile`、`docker-compose.yml`。

## 5. 候选生图与阶段 03 人工换图

- 每个 `generated_candidate` 资产组首轮自动生成 2 张；
- 每轮保存实际提交给模型的完整提示词、模型、候选 ID 和时间；
- 首轮完成后前端显示“查看生图提示词”和“更换产品图并重新生成”；
- 同一目标 SKU 只显示一个“人工修正目标 SKU 身份图”窗口；窗口内先选择要修正的上游节点，再从该节点当前产品形态的合法 OSS 资产中改选，服务端再次校验资产属于当前 SKU；
- 场景候选节点与独立产品资料节点继续保持节点级映射，避免正面、背面、盒装、瓶装等不同语义被一张图错误覆盖；统一窗口根据节点类型自动切换“重新生图”或“OSS 原图直连”动作；
- 场景节点改选后同时更新节点 `targetAssetId`、生图身份参考和 OpenCV 几何 manifest/布局层，只为当前节点生成下一轮，其他节点与旧候选保持不变；
- 独立产品资料节点改选后直接替换为所选 OSS 原图，不调用生图；
- 用户可以填写下一轮纠偏补充，也可以留空重新采样；下一轮提示词固定为“首轮完整基线 + 人工纠偏补充 + 同一平台安全约束”，人工内容不能覆盖首轮基线；
- 每轮生成 2 张且旧结果全部保留；单资产最多 3 轮，第 4 轮由服务端阻断；
- 源图复用节点不显示产品图调整或重新生成入口。

## 6. 前端变化

阶段 03：

- 删除智能数量匹配、投影面积、数量加减器、自动排列和严格数量门禁；
- 对含产品的场景图显示 OpenCV 数量核验状态；数量与槽位冲突时显示观察数量、可靠实例框数量、重新识别和人工确认入口，修正前禁用映射确认；
- 展示全部源资产的序号、标签、nodeKey、角色、审计理由、路由和几何状态；
- 上游文本节点展示自动 SKU 改写稿并按原 content 条数逐条开放人工编辑；用户点击映射确认后才持久化为目标文本资产并进入后续画布，删除原 nodeKey 引用、残留源 SKU 或混入其他 SKU 时服务端阻断；
- 审计冲突节点显示强制重构提示，不显示源图复用开关；
- 候选图按轮次分组，每轮有“查看生图提示词”按钮；
- 每个 SKU 仅提供一个目标身份图人工修正窗口；选择场景节点时提供“更换产品图并重新生成”和选填纠偏文本，选择 OSS 直连节点时提供“确认更换本节点产品图”且不调用生图；
- 视频提示词区域明确说明不会提交几何、OSS ID、映射和数量模板。

## 7. 预检与质检

资产预检：

- 全部源 nodeKey 已路由；
- 含产品场景图已有首轮 2 张候选；
- 独立产品资料图走目标身份图直连；
- 冲突节点未走源图复用；
- 用户为每个资产组选择了候选；
- 视频提示词不存在资产指令泄漏和旧 SKU 残留。

生图后检查旧产品、旧包装、旧文字和重影是否清除，目标 SKU、Logo、标签、结构和比例是否正确，以及人物、背景、手部、承托、遮挡和构图是否保持。若失败，返回对应资产组重新生图，不能依靠视频二轮解决已经固化在上游图中的错误。

视频质检以已确认上游资产为数量与布局事实，不重新规划产品数量。
