# 一键换品：新首帧候选反馈与口播决策边界 v2.11.26

状态：已随 v2.11.26 发布；PR #184，生产流水线 #207 success
日期：2026-08-21
阶段分支：`fix/replacement-pending-first-frame-voiceover-decision-v21126`
主线基线：`origin/main@cb01563`（应用版本 v2.11.25）

## 1. 本阶段解决的问题

1. 用户点击“+ 新首帧”后，旧接口会一直等待图片模型完成才返回，页面期间没有新的版本 Tab，用户容易误判为点击未生效并重复操作。
2. “口播安排”虽然直到视频任务提交前都没有进入音频方案、提示词和 LibTV 编译，现有页面却在创建一键换品任务时立即锁死“沿用旧口播 / 使用新口播”和文案，锁定时间早于真实制作边界。

本阶段不改变首帧作为 `initial_state_anchor`、ShotPlan 锚点重构、资产权威、产品状态链和视频提示词规则，只修正候选反馈时机和口播决策时机。

## 2. 最终交互规则

### 2.1 “+ 新首帧”

- 点击瞬间，前端按当前最大版本号加一，立即插入并激活 `新首帧 Vn` 占位 Tab。
- 占位候选显示“准备输入素材”等生成阶段，不等待图片结果回传。
- 后端先持久化正式 `generating` 候选，再以 HTTP 202 返回；实际图片生成继续在后台运行。
- 前端用服务端正式候选替换乐观占位候选，并继续轮询阶段、成功图或失败原因。
- 同一任务已有 `generating` 候选时禁止再次追加，避免版本并发冲突。
- 生成成功后继续沿用既有规则：最新成功图自动选用；用户手动改选后以手动选择为准。

### 2.2 口播安排

- 适用范围仅为“只换口播”和“产品+口播”。
- 创建任务后、视频制作提交前，用户仍可切换“沿用旧口播 / 使用新口播”，也可修改新口播文案。
- 切换选择时立即保存；新口播文案在失焦时保存，并在点击“确认ShotPlan并生成”前再次强制保存。
- 持久化的新口播仍生成版本号、SHA-256 和逐字分段，保证刷新或换设备后可恢复；这里的 `immutable` 表示已保存版本本身不可被原地篡改，不表示页面不能创建下一版本。
- 点击“确认ShotPlan并生成”后，该次请求开始进入音频方案、Compiled Video Prompt 和 LibTV 制作编译，口播决策立即关闭修改入口。
- 视频生成失败或中断、用户明确重试时，可在下一次制作提交前重新修改口播安排；历史生成记录保持不变。

## 3. 制作边界核实

口播最晚流入制作流程的时间是：

```text
用户点击“确认ShotPlan并生成”
  → 前端保存当前口播决策
  → POST /replacement-jobs/{id}/start
  → 服务端建立提交互斥锁
  → 校验最终 voiceoverMode / lockedScript
  → 编译音频切片、实际可听文本、视频提示词和 LibTV 节点
  → 创建视频任务并标记 generation_started
```

服务端使用任务级提交互斥锁。`/start` 正在处理时，另一页面或请求不能再调用口播修改接口；提交失败时释放互斥锁，提交成功后由 `generatedJobId/generation_started` 持久化锁定。

## 4. 数据与接口契约

任务增加：

```json
{
  "voiceoverDecision": {
    "schemaVersion": "one-click-replacement-voiceover-decision-v1",
    "mode": "old | new",
    "version": 2,
    "editableUntil": "video_generation_submission",
    "updatedAt": "2026-08-21T...Z",
    "lockedAt": ""
  }
}
```

修改接口：

```http
PATCH /api/product-workflows/replacement-jobs/{jobId}/voiceover-decision
Content-Type: application/json

{
  "voiceoverMode": "new",
  "voiceoverScript": "用户最终输入的逐字文案"
}
```

规则：

- `new` 必须提供非空文案；文案变化创建新的 `lockedScript.version` 和 SHA-256。
- `old` 不删除最近一次新口播快照，便于生成前切回时恢复，但执行层忽略该快照。
- 视频已提交时返回冲突错误；失败/中断后的明确重试允许创建下一决策版本。
- 历史任务没有 `voiceoverDecision` 时继续读取原 `voiceoverMode/lockedScript`，首次修改或提交时补齐新契约。

新首帧追加接口保持原 URL；增加运行选项 `returnImmediately=true`，HTTP 202 中的任务已包含正式 `generating` 候选。

## 5. 验收标准

1. 点击“+ 新首帧”同一事件周期内出现并激活 `新首帧 Vn`，无需等待网络或图片模型完成。
2. 后端在生成 Promise 未完成时已经返回，GET 任务可读到相同版本且状态为 `generating`。
3. 成功、失败、超时继续由原轮询与阶段状态处理，不丢失已有候选。
4. 只换口播/产品+口播任务创建后，两个口播选择仍可切换，新文案仍可编辑。
5. 刷新页面后恢复最近已保存的选择、文案版本和 SHA-256。
6. 点击“确认ShotPlan并生成”先保存当前选择，再以相同快照编译制作请求。
7. `/start` 处理期间和生成开始后，前端与服务端均禁止再次修改口播。
8. 视频失败/中断后的重试可重新选择口播；已完成或正在运行的任务不可修改。

## 6. 不在本阶段范围

- 不调整首帧生图提示词、模型和输入资产顺序。
- 不改变 ShotPlan 语义合并、关键帧生成顺序、库存母版或 T1—T4 分类。
- 不改变新口播逐字权威、画外音标签清洗、音色参考或成片 ASR 质检。
- 不增加口播版本管理后台；页面只显示当前已保存版本、摘要和是否已进入制作。
- 本阶段完成开发和回归后仍需另行授权才能合并或发布生产。
