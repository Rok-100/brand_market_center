# 共享 ASR 与 DeepSeek 保真校订规则

更新时间：2026-08-28

## 适用工作流

- 一键换品参考视频旧口播
- AI-KOC 原片旧口播
- 单视频批量裂变母版口播（尤其是“换文案”维度）

三处统一使用同一条服务链：参考视频 → 保留原始视频和原始音轨 → FFprobe 检测声道 → 按声道证据选择 16kHz 单声道 Diarize 或左右分轨 ASR → `XingChenAGI/XingChenASR-Diarize-V3.0` → `deepseek-v4-pro` 保真校订。

## 文本真值与模型职责

- XingChenASR 负责语音转文字、时间分段和平台实际返回的说话人标签。
- DeepSeek 4 Pro 只允许补标点、数字/英文格式、明显同音错字和极少量上下文明确的漏字。
- DeepSeek 禁止扩写、润色、概括、换句式、增加卖点或补充画面信息。
- 校订结果必须通过字符级防扩写校验：限制语义字符增长、删减和编辑距离。
- 校订请求失败、模型自报无法保真或校验不通过时，自动沿用 XingChenASR 原文，不能阻断工作流，也不能把疑似扩写写入后续提示词。
- 单视频裂变中，ASR逐字稿是 `sourceCopy` 和 `copyBeats` 的唯一文本真值；GVLM 3.1 继续分析镜头、成交结构和表演，但不得把自身识别到的更长文本拼进口播。

## 双人口播

- 16kHz 单声道只是一种 ASR 输入格式，不代表只能识别一名说话人；普通单声道或同源立体声仍交给 Diarize 模型做声纹分离。
- 原始视频及其音轨不被覆盖；16kHz WAV 都是仅用于识别、任务结束后删除的临时派生文件。
- 只有原音轨恰好为双声道，且左右声道都含有效声音、波形低相关时，才追加左右声道独立 ASR 探针。
- 左右两路还必须同时具备有效 `start/end` 时间戳，且转写文本不高度相似，才判定为“左右各录一人”并采用分轨结果；任一条件不足都回退单声道 Diarize。
- 分轨结果固定记录 `channel=left/right`，分别标为“说话人1/说话人2”，按时间戳合并；不以双声道数量直接推断有两个人。
- 不同说话人的时间段重叠时，两段都标记 `overlap=true`、`needsReview=true`。DeepSeek 不得更改这些片段，页面显示“重叠讲话，需人工核对”。
- 保留模型实际返回的 `speaker`、`start`、`end`、`segments`；单声道模型没有返回说话人标签时不伪造标签。
- 一键换品、AI-KOC 和单视频裂变页面均显示识别人数、是否左右分轨和重叠核对状态；后续提示词继续接收按说话人和时间顺序整理的分段。

## 页面交互

- AI-KOC 上传原片后自动识别旧口播，无需用户先手工录入。
- 识别完成后，旧口播填入左侧文本框；新口播为空时复制旧口播作为修改底稿。
- 两个文本框显示统一计时字符数；页面显示 ASR、DeepSeek 校订状态、说话人数、分轨状态和重叠讲话人工核对提示。
- DeepSeek 对语义字符有修改时，可展开查看未经校订的 ASR 原文；用户最终仍可人工修正。
- 单视频裂变审核页显示实际识别链路，并保留“重新识别母版口播”入口；重新识别只调用 ASR/DeepSeek，不创建视频节点。

## 密钥与缓存

- `XingChenASR` 只从服务端环境变量读取，不下发浏览器。
- DeepSeek 4 Pro 复用当前工作台账号的 FanDo 服务端模型授权，模型 ID 可由 `DEEPSEEK_TRANSCRIPT_MODEL` 覆盖。
- 转写结果按视频 SHA-256、ASR 模型和 DeepSeek 模型版本缓存；页面主动重新识别时使用强制刷新。声道策略升级会提升缓存版本，旧的单声道缓存不会复用。
- 缓存与任务审计均保存原始 ASR、最终采用文本、说话人分段和校订状态，不保存 API Key。

## 发布门禁

- 纯函数保真校验、立体声波形分析、误拆回退、双人时间合并、重叠锁定、AI-KOC 接入和裂变权威文本选择必须通过自动测试。
- 发布前用真实单人、双人、背景音乐、数字价格和品牌专名样片做探针；比对 ASR 原文、DeepSeek 校订和人工逐字稿。
- 提交、合并、部署、线上样片验证分别记录，不得把本地测试通过等同于线上发布。
