## 1. 文档目的与最终结论

本文统一“一键换品”四种替换模式中的首帧职责、连续性母版、产品身份真值、全开库存母版、关键帧依赖、资产准备顺序、视频时间线、提示词、失效传播与 QA 规则。

最终结论如下：

1. `initial_state_anchor` 与 `continuity_master` 是两个职责，允许由同一张图片同时承担，但不得继续把二者当成同一个概念。
2. 首帧由用户在首帧阶段一次性决定“沿用原片首帧”或“生成新首帧”。选择“生成新首帧”后，每张成功生成或上传的新候选自动成为当前选用图；用户仍可手动改选，删除当前图时自动回退到剩余候选中最新一张。该决定是后续执行的输入事实，ShotPlan 不再重新判断、阻断或要求用户再次确认。
3. “仅换产品/产品+口播”选择沿用原片首帧时，视为用户已经确认首帧不会影响换产品目标；原片首帧只作为最终 0 秒图，不参与 ShotPlan 产品关键帧重构。
4. “仅换产品/产品+口播”选择生成新首帧时，系统当前自动选用或用户手动改选的新首帧同时成为最终 0 秒图和 ShotPlan 连续性母版。
5. “仅换口播/仅换背景”选择沿用原片首帧且首帧含产品时，原片首帧可作为后续关键帧的产品编排母版；选择生成新首帧时，以用户最终选用的新图承担该职责。
6. T3 开箱/取出任务允许按依赖拓扑顺序先准备全开库存母版，再准备时间上更早的局部打开状态；这不改变视频的正常播放顺序。
7. 全开库存母版必须先生成并由编译器自动采用，再按依赖图生成其他关键帧；不增加第二次人工选用或确认。
8. 所有派生关键帧必须保存依赖资产 ID、SHA-256、字段锁和状态迁移契约。任一上游母版变化时，按依赖图级联失效。
9. 产品白底图决定产品身份与真实物理尺寸；首帧母版决定画面中的初始空间关系；全开库存母版决定隐藏库存；当前原片语义帧决定当前动作、机位、接触和遮挡。权威必须按维度判定，不能使用一个全局优先级。

## 2. 与现有规则和代码的冲突核对

### 2.1 无冲突、继续保留的规则

- `sourceAnalysis.sourceShots`、原片 keyframes 和硬切边界仍是只读事实层，任何首帧选择、关键帧生成、语义合并或取消都不得修改。
- `Initial State Asset` 与 ShotPlan 锚点覆盖继续独立；0 秒首帧不能替代必需的产品状态锚点。
- 生成的新首帧继续作为后续 ShotPlan 关键帧的第二张连续性参考图，并保存候选 ID 与 SHA-256。
- 开箱任务继续采用 `minimum_sufficient_physical_states_v1`、`full_reveal` 优先和 `reveal_only/cover_only` 不得改变库存的规则。
- T1—T4 分类优先级继续是 `T4 > T3 > T2 > T1`；T4 禁止自动生成，T3 使用 `global_inventory_continuity`。
- 产品白底图/产品契约继续是包装结构、Logo、标签、基础颜色、材质和真实尺寸的最高权威。
- 运输纸箱、快递外箱、填充物继续是 `transport_container`，不得作为产品替换对象。
- Merged Generation Unit、Normalized Action Timeline、Product State Chain、Person Continuity Profile、Anchor Group、Asset Manifest、Compiled Video Prompt v2 和 QA Contract 继续使用同一份规划结果。

### 2.2 需要由本文覆盖的旧规则

| 旧规则或当前实现 | 冲突 | 本文最终规则 |
| --- | --- | --- |
| 系统根据首帧产品可见性再次决定是否允许沿用 | 重复核验用户已经完成的首帧选择，并把首帧与 ShotPlan 再次耦合 | 用户一次性决定沿用或生成；后续只读取决策快照，不复核选择是否正确 |
| 沿用原片首帧时 `inventoryLayout=100` | 无产品首帧没有产品库存可锁；含旧产品首帧又不能成为目标产品库存真值 | 产品不存在时不声明库存权威；产品不替换的模式才可锁可见产品编排 |
| 仅换口播/仅换背景没有统一读取首帧人工决策 | 后续无法稳定区分最终0秒图和产品编排母版 | 四种模式统一保存一次性首帧决策；后续按模式解释母版字段，不再次询问 |
| 全开库存母版需要用户二次确认 | 与“首帧是唯一一次人工图片决策”冲突 | 编译器按规则先生成并自动采用全开库存母版，再自动生成后代关键帧 |
| 依赖图只校验 `initialStateDependency` | 全开库存母版重生后，旧依赖图仍可能继续被选用 | 所有关键帧统一保存 `anchorDependencies[]`，包括母版 ID/SHA，并执行级联失效和提交前校验 |
| 找不到 `full_reveal` 时回退到最后一个生成锚点 | 可能把局部打开状态误当完整库存真值 | T3 隐藏库存证据不足时不得静默选择最后一帧；直接进入 T4，不增加常规人工确认步骤 |
| 产品基础颜色和首帧颜色都写成高权威 | 容易把场景光照偏色误当包装基础色 | `basePackagingColor` 服从产品真值；`sceneColorRendering` 服从首帧/当前场景 |

### 2.3 结论

不存在需要推翻现有三层架构、T1—T4、产品契约或 Video Node 生成方式的架构性冲突。下一阶段是对现有实现的契约补全和流程加门，不改变原片事实层，也不重排视频动作时间线。

## 3. 统一术语与三层结构

### 3.1 资产和规划术语

- `source_first_frame`：从参考视频实际 0 秒提取的原片首帧。
- `initial_state_anchor`：最终新视频在 `0.0` 秒必须匹配的起始状态图，只连接第一个最终 Video Node。
- `continuity_master`：关键帧生成依赖图的连续性根节点，按字段锁定人物、场景、产品尺度、产品编排等属性。
- `source_visual_continuity_master`：不修改视觉的任务中，由原片首帧承担的完整视觉母版。
- `foreground_product_arrangement_master`：仅换背景时，由原片首帧承担的人物和产品前景母版，不提供目标背景权威。
- `background_initial_state_master`：仅换背景时，用户选用的换背景新首帧，负责最终背景和 0 秒状态。
- `product_identity_truth`：目标产品白底图/产品参考图及产品契约。
- `canonical_inventory_anchor`：能完整确认隐藏库存数量、排数、层数、顺序、朝向、间距和包装层级的全开库存母版。
- `product_state_anchor`：某个动作阶段的产品状态关键帧。
- `timeline_evidence`：只提供动作时间定位的纯语义帧，不连接 Video Node。
- `anchor_dependency_graph`：从连续性母版和库存母版到派生状态锚点的有向无环依赖图。
- `transition_contract`：每个状态锚点允许变化和必须继承的字段契约。

### 3.2 三层结构

```text
事实层（只读）
sourceShots / source keyframes / actionPhases / personTracks
first-frame product evidence / productLocator / hard cuts
        ↓
规划层（可重建）
ShotPlan / Merged Generation Unit / Product State Chain
Continuity Master Profile / Canonical Inventory Plan
Anchor Dependency Graph / Transition Contract
        ↓
执行层（每次重新编译）
Anchor Input Manifest / Anchor Generation Prompt v2
Video Asset Manifest / Compiled Video Prompt v2 / QA Contract
        ↓
图片生成节点 / 最终 Video Node / QA Node
```

## 4. 四种替换模式的最终首帧决策

### 4.1 一次性首帧决策快照

首帧选择是用户在首帧阶段完成的一次性人工决策。系统只持久化结果和资产完整性，不在 ShotPlan、关键帧生成、Video Prompt 或 QA 阶段重新判断用户是否应该沿用原片：

```json
{
  "firstFrameDecision": {
    "strategy": "reference",
    "selectedAssetId": "reference-first-frame",
    "candidateId": "reference-first-frame",
    "sha256": "...",
    "decidedBy": "user",
    "decidedAt": "2026-08-21T00:00:00.000Z",
    "decisionFinal": true,
    "shotPlanRevalidation": "forbidden",
    "changePolicy": "only_explicit_user_change"
  }
}
```

执行规则：

- `strategy=reference`：原片首帧直接作为最终 0 秒资产。
- `strategy=generated/custom`：用户最终选用的生成图或自定义图作为最终 0 秒资产。
- ShotPlan 可以读取首帧图片并按模式编译连续性字段，但不得重新判断 `strategy`，不得因检测到产品、背景或其他内容改写用户选择。
- 后续只校验 `selectedAssetId/candidateId/sha256` 是否仍与依赖快照一致；这是资产完整性校验，不是首帧决策复核。
- 只有用户明确改选或重新生成首帧，才更新该快照并触发依赖图失效。
- 不增加首帧产品可见性门禁、二次确认弹窗或新的付费视觉核验。

### 4.2 模式决策矩阵

| 替换模式 | 用户首帧决策 | 最终 0 秒图 | 连续性母版 | ShotPlan 关键帧行为 |
| --- | --- | --- | --- | --- |
| 仅换产品 | 沿用原片 | 原片首帧 | 只锁人物、场景、机位、光线、构图；按用户判断不建立产品母版 | ShotPlan 独立重构产品关键帧，原片首帧不进入产品关键帧生图输入 |
| 产品+口播 | 沿用原片 | 原片首帧 | 与仅换产品相同 | 视觉逻辑与仅换产品相同，口播链路独立 |
| 仅换产品/产品+口播 | 生成新图 | 用户选用的新首帧 | 锁人物、场景、目标产品初始尺度、可见数量、方向、布局、接触和遮挡 | 新首帧作为关键帧依赖图根节点 |
| 仅换口播 | 沿用原片或生成新图 | 用户最终选定的首帧 | 锁定选定首帧的完整视觉；有产品时可锁产品数量、方向、形态和编排 | 默认不生成视觉锚点；母版只进入 Video Prompt、Asset Manifest 和 QA |
| 仅换背景 | 沿用原片 | 原片首帧 | 锁人物、产品身份、数量、尺度、方向、形态、前景遮挡和用户接受的0秒状态 | 后续换背景关键帧自动按当前语义帧和产品编排母版生成，不回头复核首帧选择 |
| 仅换背景 | 生成新图 | 用户选用的换背景新首帧 | 锁人物、产品编排、目标背景和最终0秒状态 | 后续换背景关键帧继承该母版自动生成 |

### 4.3 前端按钮语义

- 首帧阶段只出现一次“沿用原片首帧 / 生成新首帧”人工决策，不在 ShotPlan 或关键帧区域重复出现首帧确认。
- 用户完成选择后显示“首帧决策已锁定”；后续只允许用户主动返回首帧区域改选。
- ShotPlan 仍保留现有确认、语义合并和“与上一个镜头共用关键帧”操作，但这些操作不得改变首帧决策。
- 不新增复杂管理页、产品可见性门禁或母版二次确认，只显示自动生成进度和因首帧主动改选而过期的关键帧数量。


首帧母版只锁定“初始状态”。后续有明确动作证据时，允许按 `transition_contract` 改变状态，不能用首帧把动作强行冻结。

### 6.2 模式化锁定范围

- 换产品且用户决定沿用原片首帧：`locks` 不含任何产品字段，`participatesInShotAnchorGeneration=false`；系统不再通过产品可见性检测复核该决定。
- 换产品且使用生成新首帧：锁定可见产品初始状态；隐藏内容物仍由全开库存母版或原片明确证据决定。
- 仅换口播：锁定原片完整视觉，但不触发视觉锚点生成。
- 仅换背景原片首帧：锁定人物和产品前景，不锁背景。
- 仅换背景新首帧：锁定目标背景及融合后的最终 0 秒状态；产品身份仍服从原片前景母版。

## 7. T3 全开库存母版与资产准备顺序

### 7.1 两种顺序必须分离

`assetPreparationOrder` 是依赖拓扑顺序，可以与时间相反：

```text
全开库存母版生成并自动采用 → 局部打开状态 → 其他依赖状态
```

`normalizedActionTimeline` 和最终视频播放顺序始终按原片：

```text
闭合 → 打开一点 → 部分露出 → 完全打开 → 取出/使用（若原片存在）
```

图片资产先生成全开状态，不代表视频倒序生成，也不改变 Video Node 的动作提示词时间线。

### 7.2 Canonical Inventory Anchor 选择规则

候选优先级：

1. 能完整看到容器内部且库存边界清晰的 `full_reveal`。
2. 多张互补视角能无冲突确认同一库存，但多视角透视无法统一时进入 T4。
3. 原片没有足够完整的库存证据时进入 T4；不得把最后一张局部露出帧静默当作完整库存母版，也不得增加常规人工确认步骤。

库存母版必须保存：

- 容器 ID 与产品层级；
- 目标产品单件真实尺寸模板；
- 来源库存证据；
- 目标库存总数、列、行、层、顺序、方向和间距；
- 产品数量策略；
- 编译器自动采用的候选 ID、SHA-256、采用时间和规则版本；
- 是否与目标产品真实尺寸物理兼容。

### 7.3 产品真实尺寸与库存排布冲突

不能为了保持原片数量，把目标产品缩小、压扁、拉伸或互相穿插。编译库存母版前先执行：

1. 读取产品契约真实尺寸。
2. 读取原片容器可见空间和库存排布证据。
3. 应用用户数量策略：保持原数量、保持原区域体积自动调整数量或指定数量。
4. 若“保持原数量”与目标产品真实尺寸明显不兼容，不能静默修改尺寸；直接进入 T4，由用户回到已有任务配置修改数量策略或产品资产后重新执行。
5. 一旦目标库存母版自动采用，后续状态只允许由真实取出、放入、消耗或重排动作改变。

### 7.4 `仅换产品-绿盒眼.mp4` 样例

抽帧证据：

- 约 0—1 秒：绿色运输纸箱闭合，目标产品不可见。
- 约 1.5 秒：局部打开，露出一列连续 6 个产品。
- 约 2—3.5 秒：完全打开，清楚显示 4 列 × 6 个，共 24 个产品。
- 原片没有取出、放入、消耗或重排，只有箱盖角度和遮挡范围变化。

该样例的资产准备顺序：

1. 闭箱状态识别为 `transport_container + pre_reveal`，产品不可见，不生成换品状态锚点，沿用原片事实。
2. 使用全开原片语义帧、已选新首帧（若存在）和目标产品真值图，先生成 4×6 全开库存母版。
3. 生成结果先通过确定性的状态类型、资产 ID/SHA、产品真值输入和依赖完整性检查，由编译器自动采用并记录 ID/SHA；不暂停、不要求用户二次选用。产品像素身份、数量与排布的视觉质量仍由后续成片 QA/用户验收负责，本阶段不伪称结构检查能够看懂生成图片。
4. 使用自动采用的母版生成局部打开状态；只改变箱盖角度、手部位置和可见遮挡，局部可见的一列必须与母版的 6 行一致。
5. 最终 Video Prompt 仍按闭箱 → 局部打开 → 全开顺序生成。

若目标产品真实尺寸无法以 4×6 放入同一运输纸箱，则第 2 步必须按数量策略重新确定目标库存，不能缩小产品伪造 24 个。

### 8.4 生成门禁

- 依赖 `canonical_inventory_anchor` 的节点只有在母版 `status=auto_adopted/user_selected`、具有 ID/SHA 且确定性结构 QA 通过时才能生成。

### 8.5 级联失效规则

| 上游变化 | 失效范围 |
| --- | --- |
| 用户主动改选/重生连续性首帧母版 | 所有依赖该母版的库存母版和状态锚点 |
| 全开库存母版自动重生、重新采用或删除 | 所有局部打开、关闭、取出、放入、展开等后代锚点 |
| 产品参考图集合、产品契约或数量策略变化 | 所有目标产品库存母版和状态锚点 |
| 某个 source keyframe 或所属 sourceShot 重新分析 | 该来源节点及其后代 |
| 用户取消“与上一个镜头共用关键帧” | 受影响 Merged Generation Unit 的依赖图重建 |
| 只修改视频目标时长 | 不重生图片，只重映射 Normalized Action Timeline |
| 只修改口播文案或音频策略 | 不重生视觉关键帧 |

失效只删除规划层的选用关系并将派生候选标记为过期，不删除原始 `sourceShots`、source keyframes 或历史生成文件。

## 9. Transition Contract

### 9.1 通用字段

```json
{
  "type": "remove_item",
  "preconditions": ["inventory_anchor_auto_adopted", "item_visible_or_reachable"],
  "allowedChanges": [],
  "mustInherit": [],
  "inventoryDelta": {
    "insideContainer": -1,
    "heldByPerson": 1,
    "totalSceneInventory": 0
  },
  "evidenceActionId": "action-03"
}
```

### 9.2 状态变化矩阵

| transitionType | 允许变化 | 必须继承 |
| --- | --- | --- |
| `reveal_only` | 箱盖角度、可见范围、手部位置、遮挡 | 总库存、行列层数、排列、产品尺度、身份 |
| `cover_only` | 遮挡增加、盖子关闭角度 | 总库存、排列、身份、未移动产品位置 |
| `remove_item` | 容器内减少一件、手中增加同一件、接触点和遮挡变化 | 场景总数不变、其余库存排列、产品身份和尺度 |
| `insert_item` | 手中减少一件、容器内增加同一件 | 场景总数不变、未受动作影响的库存 |
| `rearrange` | 原片明确移动的产品位置、顺序、间距 | 总数、产品身份、真实尺寸 |
| `hold/display` | 产品随手部移动和合理转向、识别面变化 | 产品身份、真实尺度、场景、人物；无依据不得改数量 |
| `open/close` | 零售包装或直接容器的开合角度和遮挡 | 产品层级、身份、内容物数量；除非动作同时含取出/放入 |
| `unfold/fold` | 内容物形态、展开范围、接触点 | 内容物身份、材质、数量和真实人体比例 |
| `dispense` | 容器内容量合理减少、内容物位置和形态变化 | 容器身份、手部接触和物理流向 |
| `apply/use` | 内容物从手/工具移动到使用部位 | 产品身份、人物身份、使用部位和原片动作因果 |
| `preserve/unknown` | 只允许明确可见的机位和遮挡差异 | 数量、尺度、身份、排列和产品状态全部保持；证据不足不得猜测 |

没有 `remove_item/insert_item/rearrange/dispense` 等明确库存动作时，不得增加、减少、复制或重排产品。

## 11. 最终端到端生成逻辑

### 11.1 任务准备

1. 用户选择替换模式并上传参考视频。
2. 系统提取真实 0 秒首帧并完成来源分析。
3. 保持 `sourceShots` 事实层不变，生成 ShotPlan、T1—T4 分类和 Generation Planning。
4. 用户在首帧区域一次性决定沿用原片或生成新图；系统持久化 `firstFrameDecision`，后续流程只读取该决策和选定资产，不编译首帧产品可见性门禁。

### 11.2 首帧一次性决策

1. 用户选择“沿用原片首帧”时，立即把原片首帧登记为 `initial_state_anchor`。
2. 用户选择“生成新首帧”时，继续使用：图 1 原片真实首帧 → 图 2..N 首帧产品素材；用户选定一个最终候选后登记为 `initial_state_anchor`。
3. 系统按替换模式从同一选定资产编译零个或多个 `continuity_master`，但不得重判或推翻首帧策略。
4. 首帧决策完成后直接进入 ShotPlan；后续关键帧流程不再出现首帧核验、首帧确认或首帧选用步骤。
5. 只有用户主动返回首帧区域改选时，才先执行依赖图级联失效，再重新生成受影响关键帧。

### 11.3 ShotPlan 与关键帧资产准备

1. 根据 Product State Chain 标记每个状态的 `transitionType` 和库存变化。
2. T1/T2 按最小必要产品状态锚点生成。
3. T3 先选择最完整库存证据，建立 `canonical_inventory_plan`。
4. 生成全开库存母版，确定性结构 QA 通过后由编译器采用并记录 ID/SHA、规则版本和库存契约；原片证据不确定时进入 T4，图片任务失败或结构依赖失败时停止后代生成并允许重试。
5. 构建 Anchor Dependency Graph、Transition Contract 和拓扑顺序。
6. 按拓扑顺序自动生成并采用依赖关键帧；每张都使用实际 Input Manifest 编译 Prompt。
7. 每张关键帧自动 QA 通过后刷新覆盖矩阵；失败、依赖不匹配或 T4 才中断，不以首帧满足 ShotPlan 覆盖。

### 11.4 视频执行编译

1. 保持 Normalized Action Timeline 的原片时间顺序。
2. 编译 Video Asset Manifest：完整参考视频、最终 0 秒首帧、目标产品真值图、自动采用的状态锚点和音频。
3. 纯语义时间帧只进入 Prompt 时间轴，不连接 Video Node。
4. 校验所有 `connectToVideoNode=true` 的真实 nodeKey。
5. 校验首帧、库存母版和状态锚点的依赖 ID/SHA。
6. 编译 Compiled Video Prompt v2 和 QA Contract。
7. 只有第一个最终 Video Node 连接全局 `initial_state_anchor`；硬限制分段后的后续节点使用所属状态锚点。

### 11.5 视频生成与 QA

1. Video Node 按正常视频时间线生成，不使用资产准备顺序替代动作顺序。
2. QA 先按 sourceShot 检查人物、硬切、动作和边界，再按连续生成组检查状态链和依赖母版。
3. T3 检查全局库存：无库存动作时总数、行列、层数、顺序、方向和间距不变。
4. 发现依赖过期、数量突变、产品缩放伪造、旧产品残留或身份冲突时不得自动通过。

- 最终视频生成区结构不变，不向用户暴露 nodeKey、SHA、Manifest 或依赖图 JSON。

## 14. 兼容与迁移

- 现有 `initialStateDependency` 读取时迁移为 `anchorDependencies` 中的 `continuity_master` 依赖。
- 现有 `one-click-replacement-shot-anchor-input-v2` 仍可查看历史任务；新生成候选写 v3。
- 历史任务已有全开候选但没有母版 ID/SHA 时，不能直接生成新的依赖状态；重新执行自动 QA，成功后由编译器采用，失败则重生或进入 T4。
- 历史已生成视频继续回放和下载，不因新规则失效。
- 新规则不修改历史 `sourceShots`、source keyframes、已归档成片或历史 LibTV 节点。
- 旧任务证据不足时保留旧执行快照；只有用户重新生成关键帧时才强制进入新依赖契约。
- 取消共用继续从事实层重建规划，不反向解析已生成 Prompt。

## 15. T1—T4 对接

- T1：可使用单一连续性母版和最小关键状态，不要求库存母版。
- T2：每个 sourceShot 保留人物和硬切边界；只有明确共享的产品状态组才建立跨镜头依赖。
- T3：必须建立 Canonical Inventory Anchor、Anchor Dependency Graph、Transition Contract 和 `global_inventory_continuity` QA。
- T4：库存证据冲突、目标产品真实尺寸无法安全落位、多视角透视无法统一、手数冲突或母版无法通过自动 QA 时阻断自动生成。

`仅换产品-绿盒眼.mp4` 在没有额外人物/透视冲突且目标产品尺寸可兼容时应归为 T3，而不是因为资产准备顺序与时间顺序不同进入 T4。

## 19. 2026-08-21 实例守恒与新口播执行补充

### 19.1 可见产品拿取不是库存减少

从人物怀抱、桌面阵列或已可见堆叠中拿起一件产品，统一编译为 `pick_up_visible_item`，不得沿用 `remove_item`：

- `inventoryMutation=false`，拿起前后画面可见产品总数守恒；
- 只允许被拿起实例的位置、朝向、手部接触、遮挡和原支撑空位变化；
- 其余实例的中心、朝向、真实尺度、层级、接触、遮挡和运动轨迹必须继承；
- 支撑图只允许因被拿走实例而发生最小局部重力沉降，禁止整堆滑移、重排、合并、消失或复制；
- 从箱、盒、袋、包装或其他容器内部真实取出时才使用 `remove_item` 和库存变化契约。

Compiled Video Prompt、Transition Contract 与 QA Contract 必须读取同一个动作类型，并执行 `visible_product_instance_count_conserved`、`unaffected_product_trajectories_match` 和 `support_graph_change_minimal`。

### 19.2 新口播的输入原文与实际发声文本分层

“仅换口播”和“产品+口播”使用统一 `Voiceover Speech Plan`：

- 用户原文及 SHA-256 继续不可变，用于保留字符顺序和说话人指令；
- `（画外音：……）`、`（旁白：……）` 等括号标签只决定说话人，标签本身不得发声；冒号后的文本进入实际可听脚本；
- ASR 逐字验收比较实际可听脚本，不再错误要求音轨朗读“画外音/旁白”标签；
- 标点只控制停顿和语气，不作为需要朗读的字符；汉字、字母、数字、语气词、重复和顺序仍需逐字保持；
- 新口播模式提交给 Video Node 的参考视频先移除旧音轨；原片音频只截取不超过约 3 秒的音色样本，`speechContent=0`、`lexicalContent=0`；
- 成片后 ASR 硬门禁、一次定向重做和最终人工复核状态继续保留，不能因提示词增强而取消验收。

以上补充不改写原始 `sourceShots`，不改变 ShotPlan 视频时间顺序，也不影响 T3 全开库存母版的资产准备拓扑。
