# AI-单视频批量裂变技术方案

## 1. 目标

输入一条已经验证有效的视频，由LibTV识别并锁定核心成交逻辑，选择需要变化的维度，批量输出 1-10 条逻辑一致、表现多样的新视频。

可选变化维度：

- 换产品
- 换背景
- 换口播文案与字幕
- 换服装颜色
- 换主角形象
- 多个维度组合变化

系统必须保留人工审核，不能把未经确认的产品包装、价格、功效或人物形象直接输出为可投放成片。

## 2. 推荐工作流

1. 上传单条原片。
2. AI识别原片结构：分镜、时长、人物、产品、背景、服装、口播、字幕、BGM和关键动作。
3. 用户选择“要变什么”和“必须保持什么”。
4. 系统按目标数量生成1-10张独立裂变任务卡；不直接做笛卡尔积，避免出现人物、产品、文案和场景互相冲突。
5. 按分镜分别执行替换，不直接对整条视频做不可控的全局重绘。
6. 自动统一画幅、帧率、音量和分镜顺序，生成完整预览。
7. 人工审核问题分镜，只重做失败镜头。
8. 审核通过后批量导出。

## 3. 原片分析层

原片上传后先生成结构化 JSON：

```json
{
  "duration": 38.2,
  "ratio": "9:16",
  "shots": [
    {
      "index": 1,
      "start": 0,
      "end": 4.8,
      "speaker": "主角",
      "productVisible": false,
      "background": "卧室梳妆台",
      "wardrobe": "浅蓝上衣",
      "action": "面对镜头说话",
      "voiceover": "……",
      "replaceable": ["background", "wardrobeColor", "protagonist"]
    }
  ]
}
```

分析内容至少包括：

- ASR口播转写、角色和时间戳
- 镜头切分与关键帧
- 产品连续露出次数和时间段
- 人物身份、站位、姿态和手部动作
- 背景与服装颜色
- 原生字幕、贴纸、包装文字和水印
- 原声、BGM、环境声的组成
- 哪些镜头适合替换，哪些镜头需要保留原片

## 4. 五种裂变能力

### 4.1 换背景

- 对人物和产品进行视频分割。
- 保留人物动作和产品，重绘背景。
- 统一光线、接触阴影和景深。
- 第一阶段优先做静态或轻微运动背景。

这是最适合先做的能力，原片人物、口播和动作都可以保留，失败范围较小。

### 4.2 换服装颜色

- 锁定服装区域蒙版。
- 只修改颜色、材质倾向，不改变领口、版型和身体结构。
- 对整段进行时序一致性检查，避免衣服颜色闪烁。
- 涉及领口和身体暴露时必须人工审核。

### 4.3 换产品

- 从产品资产库选择目标产品正面、侧面、开盖、质地和使用图。
- 检测原片每次产品出现的位置、角度、遮挡和手部关系。
- 产品镜头使用目标产品参考图重新生成。
- 非产品镜头保持不变。
- 生成后检查包装颜色、盒型/瓶型比例、logo方向、固有文字和产品数量。

产品替换不能只做贴图。手持、开盖、涂抹、上脸等镜头需要按动作和遮挡关系重新生成。

### 4.4 换文案与声音

- ASR锁定原口播时间轴。
- 新文案按原片语速重新分段，单段不超过模型时长。
- 使用TTS或授权音色生成新口播。
- 必要时进行嘴型同步。
- 字幕根据新口播重新生成。
- 原BGM和环境声保留，新旧人声不得叠加。

音频建议拆成三轨：`voice`、`BGM`、`ambience`。初期如果人声/BGM分离不稳定，保留人工审核和剪映补救环节。

### 4.5 换主角形象

- 锁定姿态、机位、动作和角色关系。
- 通过用户确认的人物基准图保持身份一致。
- 每个镜头生成后进行人脸、发型、服装和身体一致性检查。
- 双人视频需分别锁定两个角色，不能发生角色互换。

这是风险最高的能力，应最后开发，并限制为已授权人物或AI虚拟人物。

## 5. 系统架构

```text
工作台页面
   ↓
任务与审核服务
   ↓
原片分析器 → 分镜JSON / 转写 / 关键帧
   ↓
裂变任务矩阵
   ↓
LibTV CLI执行器 → 图片/视频/音频模型
   ↓
FFmpeg或云端媒体服务 → 统一格式 / 拼接 / 混音
   ↓
人工审核 → 单镜重试 → 批量导出
```

当前电脑不适合承担长期渲染时，可把“LibTV执行器”和“拼接服务”放到云端按任务运行；同事仍然只使用工作台页面。

## 6. 页面设计

第三入口采用五步工作流：

1. 上传原片。
2. 查看并修正AI拆解。
3. 勾选裂变项和目标数量。
4. 配置目标产品、背景、文案、服装颜色或人物资产。
5. 预览任务矩阵，审核后生成。

结果页按“成片 → 问题分镜 → 重试”展示，不把所有技术参数暴露给普通使用者。

## 7. 开发顺序与验收标准

### 第一阶段：母版逻辑锁与1-10条任务卡

- 自动识别钩子、痛点、解决方案、卖点、人物关系、行动引导和镜头功能。
- 可选择稳健、均衡、大胆三种强度，并生成1-10张独立任务卡。
- 人工确认核心逻辑、参考资产和任务卡后才进入生成。

### 第二阶段：换产品

- 只替换指定产品镜头。
- 产品包装、颜色、比例和logo方向通过人工审核。
- 缺失产品动作镜头能从产品库调取或单独生成。

### 第三阶段：换文案与声音

- 新口播逐字正确。
- 新旧人声不重叠。
- 字幕、嘴型和口播时间基本同步。

### 第四阶段：换主角与表现形式裂变

- 同一条视频人物身份稳定。
- 双人角色不互换。
- 可生成最多10条任务矩阵，并只重试失败成片或失败分段。

## 8. 成本与现实边界

- 页面、任务管理和本地文件整理可以不产生订阅费。
- LibTV、Seedance、人物生成、视频重绘等模型通常会消耗模型点数，不能承诺完全免费。
- 多分镜拼接可使用FFmpeg；当前电脑缺少FFmpeg时，应改为云端按任务拼接或暂时人工处理。
- 第一版应先保证“结构正确、产品不失真、声音不混乱、能够人工纠错”，再逐步提高自动化程度。
