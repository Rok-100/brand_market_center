# 备用创意通道：本地策略与资产维护清单

## 结论

本通道采用“全局规则 → 品类规则 → SKU 档案”三层加载。产品事实和合规边界属于硬约束；场景、运镜、镜头数量和资产组合属于可持续迭代的策略。两份产展沉淀文档同时包含通用经验与黑晶案例，不应整份只当作黑晶档案，也不应在每个 SKU 任务中原样全文注入。

运行时由服务端 `creative-instruction-showcase-v2@2026.08.24-r3` 编译器加载已版本化的规则摘要；浏览器只提交手选分类、生成数量、自然指令和任务资产，不直接读取 Skill，也不调用 Codex。7 款 SKU 的名称、规格、尺寸、人体比例和数量策略统一读取 `app/assets/product-workflows-runtime/product-profiles.json`。8 个商业分类、每类 20 个场景由服务端场景库 `skincare-purpose-scene-library@2026.08.20-r1` 提供。

## 必须持续关注的本地资产

### 通用产品事实资产

每个 SKU 至少维护以下角色，并避免把相似图片无差别全传：

1. 正面/标签图：锁定产品身份、品牌、固有文字区域与主色。
2. 侧面、顶部或三视角图：锁定厚度、开合结构和立体比例。
3. 单体/直接容器/单片包装图：锁定实际使用单元，不能与外盒互换。
4. 内容物或质地图：只在真实使用、开袋、展开、上脸或质地镜头中使用。
5. 已审核规格和合规资料：属于硬事实，不从自然指令或模型输出中推断。
6. 多件抱持与陈列：先用 `scaleReference` 锁定人体/手部比例，再用 `quantityStrategy` 按占用区域、重心、遮挡和承托能力重算数量；不得机械继承旧品件数。

## 建议建立的持续优化闭环

每个正式生成样本至少记录：SKU、是否上传场景图、产品图文件名与角色、模型/模式/时长、模板版本、规则版本、最终提示词、结果路径和失败标签。重点统计以下失败标签：

- 包装/文字/颜色/材质漂移。
- 同款产品比例不一致，靠缩小制造数量感。
- 盒装、单片袋、内容物角色混用。
- 开袋第一形态错误、膜布纹理或湿润度错误。
- 场景残留、产品悬浮、遮挡/阴影/反射错误。
- 镜头过少、全程静止、快速跳切或无来源特效。
- 新增字幕、卖点字、功效宣称或触发卡审禁区。
- 模型能力、参考图数量或生成模式与预检不一致。

只将跨多个 SKU、多个模型仍稳定成立的结论上升为全局规则；只在面膜类稳定成立的进入品类规则；包装、规格、膜布状态和卡审词等仅进入对应 SKU 档案。每次规则变更必须提升版本号并运行 0/1/9/10 张边界、两种场景链路、通道切换不串台和原通道回归测试。
