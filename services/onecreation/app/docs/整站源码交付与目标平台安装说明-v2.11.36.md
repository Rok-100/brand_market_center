# 整站源码交付与目标平台安装说明（v2.11.36）

## 1. 交付结论与版本基线

- 交付形态：完整视频工作台源码，不拆分“一键换品”和“AI 产品镜”。
- 应用版本：`v2.11.36`。
- 业务代码基线：`origin/main` 的 `73ebb97861d56c488ac75b002eee42ffbc5fd31f`；正式交付包还应包含其后的交付整理提交，并在交付清单中记录最终完整提交 SHA。
- 一创创作功能区入口：`/creation-workbench.html`。
- 一键换品入口：`/replace-product.html`。
- AI 产品镜入口：`/product-studio.html`。
- 视频提示词逆推入口：`/video-prompt-reverse.html`。

这两个入口共用同一个 Node.js 服务、登录鉴权、LibTV 适配、模型凭据、素材中心、产品工作流运行时、任务中心和持久化目录。因此，交付时必须保留整站目录结构，不能只复制两个 HTML/JavaScript 页面。

## 2. 源码包应包含的内容

- `app/`：服务端、前端页面、工作流逻辑、插件、静态资产和自动化测试。
- `config/`：非敏感的产品和工作流配置。
- `deployment/`：反向代理模板及部署辅助文件。
- `docs/`、`README.md`、`ONLINE-DEPLOYMENT.md`：功能、部署和接续文档。
- `Dockerfile`、`docker-compose.yml`、`.dockerignore`：容器构建与运行配置。
- `.env.example`：无密钥环境变量模板。
- `app/assets/workbench-auth/auth-config.example.json`：无密钥鉴权配置模板。
- `tools/`、`runtime/` 中被 Git 跟踪的必要运行文件。

源码包必须通过 `git archive` 或等价的“仅打包 Git 跟踪文件”方式生成。不要直接压缩开发工作目录。

## 3. 源码包不得包含的内容

- `.git/`、开发分支元数据和本地编辑器配置。
- `.env`、`.env.*`（`.env.example` 除外）、`secrets/`、`app/auth-config.json`。
- `runtime-data/`、`app/jobs/`、`app/uploads/`、`app/outputs/`、`app/cache/`、`app/updates/`。
- 用户上传素材、生成成片、任务记录、日志、备份、数据库导出文件和 LibTV/可灵登录凭据。
- 任何真实 API Key、访问令牌、私钥、数据库密码或生产域名专用密钥。

源代码、配置密钥和业务数据是三份独立交付物。若领导需要迁移历史任务和素材，应另行制定加密的数据迁移方案，不能把数据直接混入源码 ZIP。

## 4. 目标平台前置条件

- 推荐 Linux x86_64 主机，已安装 Docker Engine 与 Docker Compose v2。
- 公网或内网 HTTPS 域名，以及可以配置长连接、大文件上传和 3600 秒超时的 Nginx/网关。
- 可访问镜像构建依赖、LibTV、公司鉴权、公司模型、素材数据库/OSS 以及实际启用的第三方模型服务。
- 两个仅绑定 `127.0.0.1` 的空闲端口，默认主服务 `3766`、明星画面服务 `3767`。
- 足够的持久化磁盘；视频上传、缓存和输出会持续增长。

镜像基于 Node.js 22，并安装 `ffmpeg`、`ffprobe`、LibTV Linux CLI 与可灵中国区 CLI。不要把 Windows 开发机上的用户凭据或缓存复制进 Linux 容器。

## 5. 无密钥配置

### 5.1 环境变量

在目标服务器根目录执行：

```bash
cp .env.example .env
```

至少需要按目标平台填写：

- `HOST_PORT`、`PERSON_HOST_PORT`：宿主机本地监听端口。
- `WORKBENCH_IMAGE`：建议使用带版本号的镜像名，例如 `brand-marketing-workbench:2.11.36`。
- `PUBLIC_URL`：工作台完整 HTTPS 外部地址，不要以 `/` 结尾。
- `RUN_UID`、`RUN_GID`：拥有 `runtime-data/` 的宿主机用户和组。
- `AI_WORKBENCH_INTERNAL_TOKEN`：目标服务器新生成的高强度随机值。
- `WIS_CENTRAL_ACCESS_URL`：中枢权限中心的工作台身份授权接口，生产环境必须配置 HTTPS 地址。
- `WIS_WORKSTATION_API_TOKEN`：中枢权限中心签发给工作台的服务令牌；只能保存在服务器 `.env` 中，禁止进入镜像、源码包或前端。
- 数据库、OSS、模型服务和千川相关变量：只填写目标环境实际启用的能力。

`.env.example` 中敏感项均为空，不是可直接用于生产的凭据。填写后的 `.env` 只能保存在目标服务器，禁止放回源码包、镜像或聊天记录。

### 5.2 登录鉴权

在目标服务器执行：

```bash
mkdir -p secrets
cp app/assets/workbench-auth/auth-config.example.json secrets/auth-config.json
```

把示例域名和 `replace-with-*` 占位符替换为目标平台真实的鉴权网关、协作 API Key 与公钥。`secrets/auth-config.json` 已被 Git 和 Docker 构建上下文排除，只通过只读卷挂载到容器。

目标鉴权网关至少要提供稳定用户身份，并与工作台外部地址保持正确的 HTTPS、回调和 Cookie 策略。当前登录 Cookie 使用严格同站策略；跨站嵌入或不同域鉴权必须先做兼容验证。

工作台登录成功后还会使用已验证的飞书身份向中枢权限中心复核 `ai-first-creation` 模块权限。权限中心是最终授权来源；登录授权被取消、界面权限被收回或权限中心不可达时，工作台默认拒绝业务访问，不降级为放行。

## 6. 构建与启动

先创建持久化目录和鉴权文件，再构建镜像：

```bash
mkdir -p runtime-data secrets
docker compose build --pull
docker compose up -d
docker compose ps
docker compose logs --tail=200 workbench
```

`docker-compose.yml` 会把任务、上传、输出、缓存、用户配置、LibTV 凭据、素材中心和千川数据挂载到 `runtime-data/`。升级镜像时保留这些目录；首次迁移历史数据时应停服、备份并校验属主权限。

## 7. 反向代理

现有服务器参数记录在 `ONLINE-DEPLOYMENT.md`，不能原样复制到其他平台。目标平台请使用 `deployment/target-platform/nginx-location.conf.template`：

1. 把全部 `__PUBLIC_PATH__` 替换成目标路径，例如 `/ai-workbench`，不要带末尾 `/`。
2. 把 `__HOST_PORT__`、`__PERSON_HOST_PORT__` 替换成 `.env` 中的宿主机端口。
3. 将配置放入对应 HTTPS `server` 块，执行 `nginx -t` 后平滑重载。
4. 确保 `PUBLIC_URL` 与协议、域名和 `__PUBLIC_PATH__` 完全一致。

如目标网关不支持 Nginx `sub_filter`，必须先验证所有页面、静态资源、API、下载地址和 OAuth 回调在子路径下均能正确改写。

## 8. 首次初始化与账号隔离

- 用户登录工作台后，由本人完成 LibTV 手机号和短信验证码绑定。凭据按用户隔离保存在 `runtime-data/libtv/users/`。
- 公司模型授权由每位用户导入本人的 FanDo `openclaw.json`，服务端按登录账号加密隔离并换取短期令牌。
- 可灵账号仍需要在服务器环境完成绑定。
- 素材中心需要目标环境的数据库与 OSS 权限；未配置时相关能力不能视为完整可运行。
- 不要复制开发环境或原平台中其他用户的账号凭据到目标平台。

## 9. 安装验收

### 9.1 基础验收

- `GET <PUBLIC_URL>/api/ready` 返回 HTTP 200，并显示 `version: 2.11.36`，且中枢权限配置状态正常。
- `GET <PUBLIC_URL>/api/app-meta` 返回 `version: 2.11.36`。
- 未登录访问业务 API 会被鉴权拦截；完成登录后能看到当前用户身份。
- 容器重启后，任务列表、上传文件和已生成结果仍可恢复。

### 9.2 业务验收

- 首页和任务中心可正常打开。
- 一键换品能创建任务、上传参考视频与产品素材、分析、生成候选图/视频、恢复任务并下载成片。
- AI 产品镜能选择 SKU、读取关联素材、运行启用的制作通道、恢复任务并下载成片。
- 一创创作页完整显示六个功能区，每个入口均进入对应真实任务页面，而不是占位按钮。
- 视频提示词逆推能完成上传、语义分析、母提示词与分镜提示词输出，并且不调用视频生成接口。
- 收回测试账号的 `ai-first-creation` 界面权限后，已登录工作台也应被拒绝访问；恢复授权后可重新进入。
- LibTV 绑定和画布任务按登录用户隔离。
- 图片生成、视频生成、公司模型、素材数据库/OSS 逐项使用目标环境真实账号验证。

只有基础验收和业务验收全部通过，才能声明“在目标平台完整可运行”。源码测试通过或容器成功启动，不能替代真实外部依赖与业务链路验收。

2. 专项测试与完整测试结果。
3. Docker 镜像构建结果及镜像 ID。
4. 临时服务器上的基础验收和业务验收结果。
5. ZIP 文件名、文件大小与 SHA256。
6. 代码提交、合并、部署、线上核验四个相互独立的状态。

建议源码包命名为 `brand-marketing-workbench-v2.11.36-source-<短SHA>.zip`，并把 SHA256 通过独立渠道交付给接收人核验。
