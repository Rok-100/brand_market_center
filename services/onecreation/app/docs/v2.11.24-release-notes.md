# v2.11.24 发布说明

## 一键换品全开库存母版与关键帧依赖

- T3 开箱/取出任务将完整全开画面编译为 `canonical_inventory_anchor`，先生成并通过确定性结构契约校验后自动采用，再生成局部打开、取出、展开等依赖状态。
- 新生成的 ShotPlan 关键帧写入原片语义帧、已选新首帧、全开库存母版和产品真值图的资产 ID/SHA 快照，同时保存 `transitionContract` 的允许变化和必须继承字段。
- 全开库存母版重新生成或切换后，其后代关键帧会级联标记为过期、退出覆盖并按新母版自动重构；原始 `sourceShots`、原片关键帧和历史生成文件不删除。
- 最终 Video Node 提交前校验全开库存母版 ID/SHA、结构 QA 与采用状态；依赖不一致返回 `SHOT_ANCHOR_DEPENDENCY_MISMATCH`，不消耗视频生成额度。
- 同一库存连续组即使跨越多个 `sourceShot`，也复用后段可靠全开母版；资产准备顺序可以先全开后局部，但视频动作时间线仍按原片闭合、局部打开、完全打开顺序执行。

## T4 门禁与前端反馈

- 不再把最后一张局部露出帧兜底为全开库存母版；结构化开箱链缺少可靠 `full_reveal` 时进入 T4。
- 原片容器空间、目标产品真实尺寸和任务数量策略存在明确物理冲突时进入 T4，不通过缩小、拉伸或压扁产品伪造数量。
- ShotPlan 页面会在确认和生成前显示具体 T4 原因、禁用自动生成，并显示“结构契约自动校验通过”及母版变化后的自动重构进度。
- 普通剪胶带/打开零售包装但没有结构化运输箱库存链的镜头不误入 T4，原有“与上一个镜头共用关键帧”语义合并保持兼容。

## 首帧和资产权威

- 首帧与 ShotPlan 关键帧继续分开处理；用户完成沿用原片或生成新首帧的单次决策后，ShotPlan 不重复核验该选择。
- 换产品模式沿用原片首帧时，该图仍连接第一个 Video Node 并约束 0 秒人物、场景和构图，但不提供旧产品身份、数量或库存权威。
- 仅换口播/仅换背景沿用原片首帧时，原片产品身份、数量、方向和编排继续作为视觉连续性依据。

## 验证与发布边界

- 一键换品专项 166/166 通过；仓库完整回归 573/574，唯一失败为全套并发下 `libx264 malloc failed`，对应 FFmpeg 测试隔离复跑 7/7 通过。
- 发布验证只运行自动化测试、健康检查和只读页面/API 核验，不创建正式 LibTV 视频任务，不消耗视频生成额度。
