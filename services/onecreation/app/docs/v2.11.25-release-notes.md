# v2.11.25 发布说明

## 新首帧默认采用

- “生成新首帧”成功或上传自定义首帧后，系统自动采用最新成功候选，用户无需额外点击“选用”即可继续 ShotPlan 和视频生成。
- 用户手动选择任一历史候选后立即以人工选择为准；再次成功生成或上传时，最新候选重新成为默认选中项。
- 删除当前选中候选时自动回退到剩余最新成功候选；新一轮生成失败不会清除上一张有效首帧或阻断后续流程。
- 首帧 ID/SHA 发生变化时，继续使依赖旧母版的 ShotPlan 关键帧失效并重构，事实层 `sourceShots` 不变。

## 可见产品实例防漂移

- 将“从怀抱或可见产品堆中拿起一件”与“从包装内部取出一件”分开，前者编译为 `pick_up_visible_item`，不再错误触发库存重排。
- 只允许被拿起的实例改变位置、方向、手部接触和遮挡；其余产品实例的位置、方向、尺度、层级、接触关系和运动轨迹必须继承。
- 可见数量保持守恒，支撑图只允许因拿走单件产生最小局部物理沉降，禁止整堆滑动、重排、合并、消失或复制。
- 同一 `transitionContract` 同时驱动动作时间线、Compiled Video Prompt v2、QA Contract 和专属成片质检。

## 新口播逐字锁定

- 将 `（画外音：……）`、`（旁白：……）` 等说话人指令与实际可听文本分离；标签只切换说话人，本身不进入发声内容或 ASR 期望。
- “仅换口播”和“产品+口播”使用去除原音轨的参考视频执行副本，避免完整旧口播继续影响模型；原片音频只截取短音色样本，内容权威为 0。
- 用户输入文案是唯一允许发声的文本，禁止增删、润色、调序、同义替换或混入旧产品名与旧卖点。
- 成片继续执行 ASR 逐字复核；首次不一致会定向重做，仍不一致时进入人工复核，不静默判为通过。

## 验证与发布边界

- 一键换品专项测试 169/169 通过；仓库完整回归 129/129 个测试文件通过；核心脚本语法检查与 `git diff --check` 通过。
- 自动化发布只执行构建、备份、服务切换、健康检查和版本回读，不创建正式 LibTV 视频任务，不消耗视频生成额度。
