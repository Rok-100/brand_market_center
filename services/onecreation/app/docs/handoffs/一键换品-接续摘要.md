- 共享 ASR 新增声道探测：普通立体声/单声道仍走 16kHz 单声道 Diarize；只有低相关双声道再以左右两路 ASR 文本和时间戳确认“左右各录一人”。确认后按时间戳合并，重叠讲话锁定原字并提示人工核对，DeepSeek 不得猜补。

## 0G. 2026-08-21 Gitea 发布元数据编码契约

- 流水线 #204/#205 页面出现的连续 `?` 不是发布任务内的应用编码问题：对应分支原始中文提交正常，损坏发生在创建/合并 PR 和触发 `workflow_dispatch` 的元数据入口。

## 4. ShotPlan 与开箱连续性

- 原片镜头只在真实硬切、换人、换场、明显时间跳跃或镜头任务改变处拆分。
- 连续动作阶段写入 `actionPhases`，不能把抽到的每张图都当成新镜头。
- 开箱任务按“最少充分状态”选关键帧，不固定六张。典型状态为：未开箱、初露、半开、全开；实际只保留能表达真实状态变化的必要节点。
- 同一纸箱和同一批产品的数量、排数、层数、顺序、朝向必须跨关键帧一致；不存在实际取出、放入或重排时，不得虚构库存变化。
- 用户判断前后镜头属于同一连续动作时，可选择“与上一个镜头共用关键帧”；该选择同时表示建立连续生成组，不再支持“语义合并”和“沿用锚点”的矛盾组合。
- 语义合并不删除原片真实硬切或 `sourceShots`，不取消人物身份与产品状态风险；系统在规划层重算动作时间轴和连续性契约，门禁失败时保持独立生成或阻断人工确认。

## 6. 已实现并已发布的执行分类

T1—T4 是生成执行类型，不是内容题材分类。内容题材仍采用多标签。

- T1 单镜头·单产品替换：一个连续原片镜头、无硬切、无跨镜头产品状态依赖。
- T2 多镜头硬切·单产品替换：存在真实硬切，但各镜头产品状态可以独立复刻。
- T3 产品状态强关联替换：同一容器、产品阵列或库存状态跨动作/镜头连续变化，需要全局状态和锚点传递。
- T4 复杂任务/转人工：超出模型容量、无法安全拆分、字段冲突、低置信度或复杂遮挡/人物风险。

实现判定优先级：`T4 → T3 → T2 → T1`。当前阈值：`≥0.85` 自动；`0.60–0.84` 用户确认；`<0.60` 或规则冲突进入人工复核。阈值已随 v2.11.19 上线，但仍需用真实历史样本校准。
