# 一键做同款：无产品关键帧源图复用 v1

## 适用范围

当任务的“本次只允许改变”为仅换产品时，上游关键帧只有在画面中真实存在原 SKU 产品像素时才进入产品重建。人物、皮肤、腹部、手部、服装、裤子、腰带、沙发、背景以及动作语义本身都不是护肤品产品像素。

## 模型审计契约

场景图、首帧、尾帧和关键帧的 `productBearing` 是像素级判断，不是剧情相关性判断。

- `productBearing=true` 必须同时满足 `productIdentityMatchesSource=true`，并返回非空 `productPixelEvidence`。
- `productPixelEvidence` 必须说明可见的原 SKU 包装、容器、膜布、单支、内容物等产品实体及其位置。
- 仅承载人物、衣物、身体状态、动作或时序的参考图必须返回 `productBearing=false`、`productIdentityMatchesSource=false`、`productPixelEvidence=[]`。
- 模型只提到“产品相关动作”但没有提供产品身份和像素证据时，服务端不得采信 `productBearing=true`。

## 处理路由

| 源资产 | 判断 | 处理方式 |
| --- | --- | --- |
| 独立产品资产图 | 产品身份资产 | 直接替换为目标 SKU 的 OSS 原图，不生图 |
| 场景/关键帧 | 含原 SKU 产品像素且证据完整 | 进入候选图生成和人工确认 |
| 场景/关键帧 | 不含原 SKU 产品像素 | 原样复用源 nodeKey，不调用生图 |
| 参考视频 | 未命中本次替换白名单 | 原样复用 |

资产准备阶段必须再次检查映射的 `processingMode`。`reuse_source` 节点不得进入 Qwen 生图提示词编译、GPT Image 或 Seedream 调用，也不得要求目标 OSS 产品图或动作改写。

## 旧任务人工兜底

产品变更任务的每张源图片都提供同一组简洁的双向选择：“需要换品 / 直接复用”。当任务还同时更换人物或背景时，第二项显示为“不含原产品”，避免误导为整张图不再生成。用户只需看图并选择；选择立即保存，人工结论优先级高于模型结论。

- 选择“需要换品”：节点标记为含原产品，加入目标 SKU 映射和候选图生成。
- 选择“直接复用 / 不含原产品”：节点从换品映射中移除；仅换产品时复用源图，同时还有人物或背景变更时仍按其他变更生成候选图。
- 已进入映射确认阶段的任务会立即重算全部目标 SKU 映射，并清除旧的映射确认时间，防止沿用修正前的结论。
- 人工结论写回当前任务、历史源模板和 OSS/数据库快照；之后从该模板再次做同款时沿用修正后的事实。

## 疑似漏检的后台二次复核

主审模型给出“不含产品”后，服务端检查识别理由、节点附近原提示词和结构化证据。出现“拿出/手持/展示产品”等动作与“不存在/空手/遮挡”等否定结论冲突，或手部接触、低置信度信号时，才进入二次复核；明确无产品的普通帧不增加模型调用。

二次复核使用现有 Qwen 3.7 Plus 多模态通道，单次只提交当前关键帧的高清原图，并附最多 3 张源 SKU 产品身份参考图。提示词要求重点检查双手、遮挡边缘、购物袋/盒/箱开口及画面边缘的小瓶、小盒、膜布和单支产品，同时返回像素证据、归一化框和置信度。二审结果只作为预选，并在前端显示“请人工看一眼”；人工选择始终覆盖模型。

二次复核并发上限为 2，失败时保持主审路由并转人工查看，不阻断整个源画布拆解。

## 视频提示词约束

源图复用节点在最终视频提示词中必须明确：该图只作为人物、服装、身体状态、动作或时序参考，保持源图不变；不得调用生图，也不得向该图植入、移除或改造任何产品。实际产品身份仍由独立产品资产节点或经用户确认的产品承载帧提供。
